## 2026-10-08 · M0-04：加入 DeepSeek 请求配置

- **阶段/任务与状态：**DeepSeek 候选提供商的非思考模式入口完成；M0 真实验收仍待完成。
- **改动与原因：**用户提出 DeepSeek，核对官方当前模型及工具调用协议后，新增 --provider deepseek、独立 DEEPSEEK 环境配置与提供商记录。复用官方 OpenAI SDK，将请求转换为 max_tokens 和显式禁用思考，不发送未列入 DeepSeek 协议的 OpenAI 参数；标准端点不依赖 Beta strict，本地继续校验工具参数。
- **验证：**20 项测试通过；代码检查和格式检查通过。MockTransport 验证实际请求体、工具调用前缀复用、缓存命中/未命中原始字段保留，以及不回退使用 OpenAI 密钥。无配置时 DeepSeek CLI 按预期退出码为 2，没有真实模型调用。
- **限制/阻塞：**模拟 HTTP 响应不是 DeepSeek 实测；DeepSeek 凭据、模型配置和 api.deepseek.com 网络访问尚未就绪。
- **下一步：**补齐缓存用量及版本化价格核对，等待环境配置后执行真实验收。

## 2026-10-08 · M0-03：加入真实模型调用入口

- **阶段/任务与状态：**M0 的官方 SDK 适配和配置入口完成；真实调用及费用验收仍未完成。
- **改动与原因：**加入 OpenAI SDK 2.54.0 的 Chat Completions function calling 薄适配器，保留真实请求、完整响应、实际模型 ID 和原始用量；显式选择 live/synthetic 模式，缺失模型或凭据时拒绝运行。关闭 SDK 自动重试，并记录模型请求失败，避免遗漏实际调用次数；补充配置示例和真实验证说明。
- **验证：**18 项测试通过，覆盖 SDK 的模拟 HTTP 请求、原始工具调用参数保留、用量记录、429 不重试、配置缺失及 CLI 不降级；代码检查和格式检查通过。synthetic CLI 的 7 项分支检查继续通过；当前环境执行 `--mode live` 按预期以退出码 2 返回 provider_not_configured，没有发生模型请求或生成成功报告。
- **限制/阻塞：**SDK 测试使用 MockTransport，不是真实模型验证。当前环境未配置模型账户、模型 ID 或模型服务端点访问；价格版本也未确定。M0 保持进行中，尚未进入 M1。
- **下一步：**提供商、模型、凭据和端点就绪后，运行 live 验证并核对新增用量与费用，再判断 M0 是否满足完成条件。
