# M5 观察指南：操作证据与计数

参与者只看[任务卡](participant-tasks.md)。本页给主持/记录者使用，不在任务开始前讲解答案。使用[空白模板](../../examples/m5/session-template.json)，复制到独立的 artifacts/m5-study 目录后填写实际记录；模板本身保持为空。

## 开始前

记录提交、工具版本、环境和任务顺序。每人使用独立数据库/浏览器会话，先确认服务可达。统一说明模拟/真实来源和允许求助，不先演示诊断过程。工具对照按同一任务和材料进行；缺少账户/接入条件的工具记为未完成，不做无依据的能力打分。

## 计时与帮助

- 以实际时间戳记录任务开始、首次成功创建运行、提交诊断和结束；未发生留 null，不补 0。
- 从开始到结束记人工任务墙钟时间，暂停原因/区间另列；安装、环境排错、模型等待分别记录，不冒充纯诊断速度。
- 保留每次求助的问题、提供了什么帮助，以及是否代操作。没有求助只有在全程观察后才明确记录为无；未观察不是 0 次。
- 参与者停止、基础设施失败、缺资料或尚未检查到的步骤分别写出；保留在原定人数中说明，不挑选完成者作为全部分母。

## 判断依据

### T1

完成证据应包含：找到注入的首次工具超时和对应模型；只把 tool_retry_limit 从 0 改为 1；B 的第一次尝试仍超时、第二次成功；说明是执行器重试，模型未自行学会恢复。记录父运行/检查点/B ID、配置差异和具体工具步骤。B 复用首模型前缀，新增用量只涵盖后缀。协议失败未到工具的运行不能冒充该超时对照。

### T2

固定排名下 A top_k=2 缺 release-v2-fix，B 只改 top_k=3。看见元数据不等于已读取正文，读取正文不等于答案语义一定正确；过程规则和人工判断独立。记录参与者是否把材料不足直接说成编造、是否把执行成功说成答案已完全正确。模拟练习结果与真实参考结果分别记录；真实 v2 B 的 hrelease-v2 应保留引用 fail，不替换输出。

### T3

检查导入来源及历史步骤；播放只重建保存记录，不执行模型/工具。导入不带私有可恢复状态，当前入口为只读。原用量来自已保存观察，B 的继承前缀不能重复算成新增调用；金额未知不能解释为免费或实际扣费为 0。

## 原定首轮门槛与最终判断

“无需作者代操作完成一个场景”依据 T1/T2 中的诊断、单变量分支、证据核对和解释，保留逐项记录；如果帮助改变了完成过程，单列帮助后的结果，不能补称独立完成。尚未观察到的解释留未知。

原定目标为 5 位试用者至少 4 位独立完成一个场景；另核对多数人对回放/执行与未知费用的理解。记录实测人数、完成数、缺失/中止与帮助，不将预设门槛写成成绩。达到门槛也只支持首轮产品判断，不能推出统计优势。

最后按真实问题建立修正清单：对应任务/步骤、原话或证据、影响、处理提交及复核结果。助手/作者演练、自动化、工具安装记录单独归档，不能计入 5 位真实试用者。M5 最终结论只有在实操、真实试用和反馈处理都有证据后填写。
