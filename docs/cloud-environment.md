# AgentTinker 云端开发环境配置

此页描述当前架构路线 M0–M5 首版的开发环境；公开部署与托管按架构验证结果另行选择。平台配置是否保存、发布，与当前聊天绑定的实例是否采用该版本，需要分别核对。

## 设置页填写内容

| 设置 | 内容 |
| --- | --- |
| 环境名称 | AgentTinker-preview；名称便于识别，不控制项目行为 |
| 代码仓库 | 核对为 Babapei/AgentTinker-preview；工作分支沿用 work |
| 安装脚本 | 在仓库根目录执行 bash scripts/setup.sh |
| 启动技能 | 目前没有必须填写的自定义启动技能；工作规则由仓库 AGENTS.md 维护 |
| 互联网访问 | 开启；若采用域名限制，需要模型端点以及 GitHub、Python/Node 依赖下载域名。若当前选择全部访问，可沿用 |
| 网络密钥/凭据 | DEEPSEEK_API_KEY，通过平台秘密输入保存，确认供当前执行环境的 SDK 使用 |
| 环境变量 | DEEPSEEK_MODEL=deepseek-flash；是模型 ID 的字面值 |
| 可选环境变量 | DEEPSEEK_BASE_URL=https://api.deepseek.com；代码已有此默认值，通常无需填写 |
| 隐私 | 仅限自己，沿用当前开发设置 |
| VPN | 当前首版不需要 VPN |

网络密钥若要求指定目标域名，使用 api.deepseek.com。若编辑页要求配置 HTTP 认证，其对应 DeepSeek 标准认证为 Authorization: Bearer <密钥>；具体绑定方式以平台字段说明为准。仅在设置页看到密钥条目，不能证明当前进程已能使用它。

环境需提供 Python 3.12 或更高版本与 uv；React/Vite 前端阶段需要受支持的 Node.js，当前执行环境已提供 Node 24。Python 包及后续前端依赖由仓库清单和锁文件维护，安装入口保持不变。

## 安装入口

```bash
bash scripts/setup.sh
```

脚本定位自身所属仓库，执行 uv sync --locked，安装当前 Python 依赖与开发工具。它不改动网络策略、凭据或模型配置，不运行付费模型调用。前端工程及锁文件加入仓库后，在同一脚本内补充安装步骤，平台仍调用此入口。

## 生效检查与下一步

保存设置后，将配置应用到当前聊天绑定的运行实例；若平台要求重建或重启，先保留工作区文件。确认实例采用发布版本，再检查网络与秘密绑定的就绪状态、进程中的变量存在性，并通过正常 SDK 请求验证。

真实 M0 验证命令及报告说明见 [M0 验证说明](m0-validation.md)。只有实际调用和分支检查通过后，才判断 M0 是否完成。仅报告密钥是否就绪，不输出其内容。

按当前首版设计，SQLite 和文件 artifact store 位于本地，不需要额外托管数据库、向量数据库、Redis 或搜索服务账号。新增模型、外部工具或公开托管时，再补充实际采用服务的配置。
